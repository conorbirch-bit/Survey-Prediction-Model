SITE SURVEY SCHEDULING AGENT
Current application: 20.12.18
Updated: 6 November 2026

INSTALL THIS UPDATE

This ZIP is an incremental update to v20.12.17. It contains only changed
or newly required files. Extract it into the existing project folder,
replace matching files, and retain the tests/ subfolder. Keep all other
modules, your Predictive Model.xlsx, requirements and credentials.

Stop Streamlit before replacing files, then restart:
    python -m streamlit run app.py

For hosted apps, deploy all matching files together and reboot the app.
Keep building_decisions.json alongside app.py and the new Python modules.
There are no new package requirements.

SAVED AUDIT

The 231 reviewed decisions are included in building_decisions.json.
You do not need to upload the audit on every run. Upload current Salesforce
appointment/cannot-complete data each time. Completed buildings and outstanding
bookings stay excluded. A later failure expires the saved next-attempt approval.
The two missing-flat-count Saturday cases remain conditional, not guessed.

CALLS REQUIRED

Generate a normal weekly schedule to create call-ahead proposals. Use the
Calls required this week section to save contact status and notes. A Calls
Required worksheet is included in the weekly export; an updated CSV can be
downloaded after making calls. Confirm access before using provisional slots
as bookings. Changes to date, time or surveyor reset confirmation.

Call status is saved in a local SQLite database. For hosted persistence, set
SCHEDULER_STATE_DIR to a writable persistent directory. This must actually be
backed by durable storage; temporary hosting disks may be wiped on redeploy.
Do not overwrite the database during a code update. Audit decisions themselves
are stored in the deployed JSON and do not depend on session memory.

CLIENT ACCESS PLANNING

Use the separate tab and its Generate client planning schedule button.
Upload current history there, or reuse the workbook in Weekly scheduling.
Optionally supply the master portfolio for richer building/duration data.
Select recurring weekday availability, start week, survey hours and return
limit. This mode uses Monday-Friday only, repeating weeks until work is placed
or there is no feasible progress. It has no fixed week cap, no artificial
spacing and no workload spreading. Actual travel, lunch and time limits remain.

The programme assumes client-arranged access. It does not book appointments,
consume approvals, save normal call proposals or export a Salesforce upload.
The client pool now includes the approved Saturday retry buildings, planned on
weekdays. Boarded-up and construction sites are omitted. The export contains
Daily Programme and Visit Details, with Day 1 / Day 2 labels, Saturday retry
flags and manual Salesforce check dropdowns. Unplaced buildings appear in an
additional Not Scheduled tab with their reasons. The routing reference week is
not printed. Future Google journey availability can limit routing.

LIMITED SPREADING AND PROGRAMME END

Limited spreading is enabled by default. Minimum genuine utilisation defaults
to 75% and is adjustable. Spreading and added spacing cannot turn a few visits
into a full week. Short final days stay scheduled without padding. The normal
Saturday restrictions and hours remain unchanged.

End of eligible program appears only after all currently eligible sites in the
uploaded portfolio have been allocated. It does not mean they are completed.

VALIDATION

From this project folder, with existing dependencies installed:
    python -m unittest discover -s tests -v

The update is checked against the audited source data and offline routing/UI
regressions. No live Google or OpenAI requests were used during verification.
Real journey timings will be calculated when you run the app with your keys.
